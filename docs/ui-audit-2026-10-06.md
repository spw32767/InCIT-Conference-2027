### Measured contrast

Calculated using the WCAG relative luminance formula from the actual palette:

| Foreground / background | Ratio |
|---|---:|
| Slate / white | 8.58:1 |
| Slate / paper | 7.49:1 |
| Cyan / ink | 9.07:1 |
| Ink / white | 15.99:1 |
| Cyan / white | 1.76:1 |
| Slate / ink | 1.86:1 |

Ordinary text needs 4.5:1 contrast under
[WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
Keep cyan for dark backgrounds and decoration rather than text on white.

## Detailed findings

### [P2] Essential schedule details are small

- **Location:** `frontend/src/app/home.css:45`, `:48`, `:52`, with mobile
  metadata at `:73–74`.
- **Category:** Accessibility / responsive readability.
- **Evidence:** Date labels, supporting details, and the schedule disclaimer
  compute to 11px. Mobile section and mockup labels compute to 9px.
- **Impact:** Visitors must work harder to read deadlines and instructions,
  particularly on small screens or with reduced vision.
- **Recommendation:** Use a comfortable essential-content size, typically
  14–16px, while keeping clearly secondary decoration compact. Re-evaluate
  after the owner supplies the real content. Small size alone is not a measured
  WCAG failure; do not confuse good contrast with comfortable readability.
- **Suggested command:** `$impeccable typeset`.

### [P2] Mobile footer links have small hit areas

- **Location:** `frontend/src/app/globals.css:89`, `:104`, `:146`.
- **Category:** Responsive interaction.
- **Evidence:** Most footer links are 20.8px high; mobile Menu is 40px high.
  A wrapped footer link was 41.6px high. Hero buttons are 48px high.
- **Impact:** Closely stacked links require more precise taps than necessary.
- **Recommendation:** Increase the clickable height through link padding and
  make the mobile Menu comfortably sized; prefer a 44px target where practical.
- **Standard:** The WCAG 2.2 AA minimum is 24px with exceptions, including
  spacing. The existing footer spacing may satisfy that exception, so these
  measurements do **not** establish an AA violation. See
  [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- **Suggested command:** `$impeccable adapt`.

### [P2] Current Home section is not reflected in navigation

- **Location:** `frontend/src/components/site-header.tsx`, the non-group link
  `aria-current` comparison near the end of the component.
- **Category:** Navigation orientation / implementation integrity.
- **Evidence:** At `/#home`, the Home link has no `aria-current`. `usePathname()`
  supplies `/`, while navigation compares it with `/#home`. The same pattern
  affects the About and Important Dates anchors.
- **Impact:** The visual and accessible current-location signal is absent for
  the main page's section links.
- **Recommendation:** Distinguish current page from current section. Choose a
  deliberate hash/section policy, then expose the appropriate active styling
  and current-location attribute without claiming all three anchors are current.
- **Suggested command:** `$impeccable harden`.

### [P2] Footer focus outline is weak against its background

- **Location:** `frontend/src/app/globals.css:59`, `:90`.
- **Category:** Keyboard focus consistency.
- **Evidence:** The global outline uses slate, only 1.86:1 against footer ink.
  Focused footer links also gain cyan text and an underline, which remain visible.
- **Impact:** Keyboard users get an inconsistent focus-ring treatment between
  light and dark areas.
- **Recommendation:** Give dark-section controls an appropriate high-contrast
  focus outline while retaining the underline feedback.
- **Standard:** Do not report this as an established WCAG failure based on the
  outline alone: the current high-contrast underline is an additional indicator.
- **Suggested command:** `$impeccable harden`.

### [P3] Overlapping navigation rules complicate future adjustments

- **Location:** `frontend/src/app/globals.css`, initial header/navigation rules
  and the later “Conference navigation” block starting at line 127.
- **Category:** Theming / maintainability.
- **Evidence:** Brand sizes, header heights, link spacing, dropdown styling,
  and media overrides are defined in multiple passes. Supporting border colors
  also have literals alongside the new semantic tokens.
- **Impact:** Future content or component changes can accidentally revive a
  superseded style or produce inconsistent spacing.
- **Recommendation:** Consolidate when modifying navigation next; preserve
  current desktop/mobile appearance. This is not justification for a redesign.
- **Suggested command:** `$impeccable polish`.

## Positive findings

- Readable contrast for all sampled primary text combinations.
- Semantic regions, headings, main/footer navigation, image alternatives,
  a skip link, expanded states, and keyboard disclosure behavior are present.
- Shared content alignment and subtle section background changes are consistent.
- Reduced-motion preferences disable smooth scrolling and nav transitions.
- Both visible images use Next.js optimization and responsive sizes. Desktop
  requests use 256px and 640px variants, rather than the original logo bitmap
  and 1024px hero source. Above-the-fold eager loading is appropriate here.
- Montserrat is self-hosted, with its license stored alongside the font.
- Sample content is visibly labelled; the owner confirmed external services
  handle registration and payment.
- Light theme is the supported scope. Absence of a dark-mode switch is not a defect.

## Content release gates

These are expected unfinished content, not additional defect counts:

1. Replace sample dates, programme descriptions, and fictitious contacts with
   owner-approved facts. Do not treat the mockup as a source.
2. Populate secondary pages or clearly communicate pending announcements.
3. Supply the actual external registration/payment/submission destinations.
   Label destinations clearly; no internal account or payment flow is required.
4. Add final metadata and indexing decisions when factual pages and the public
   domain are ready. Preserve noindex for unfinished secondary pages.
5. Review Thai fallback typography if Thai content is added.
